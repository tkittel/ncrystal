# Space-group symmetry

## Summary

NCrystal 5.0.0 contains an exact, self-contained implementation of the 230
space groups in all 530 standard settings of International Tables Vol. B
Table A1.4.2.7: the settings table with Hermann-Mauguin and Hall symbols,
symmetry operations generated from the Hall symbols as exact integer
matrices and rational translations, and on top of them the crystal system
and setting information, cell constraints derived from the operations,
expansion of a site into its orbit and the inverse grouping, a check of a
structure against the settings of its space group, and the
symmetry-equivalent reflections (Laue classes) used by the hkl machinery.
Everything is verified against spglib and gemmi in the test suite. Before
5.0.0 the symmetry knowledge of NCrystal consisted of per-crystal-system
cell rules and tables of equivalent reflections per Laue class, assuming the
default setting of each number.

Code: `ncrystal_core/src/sgsym/`, `ncrystal_core/src/phys_utils/NCEqRefl.cc`,
the public type `SpaceGroupSettingIdx` in `NCTypes.hh`.

## Concepts

- A space group number (1-230) identifies the symmetry only up to a choice
  of setting: origin choice (24 groups have two), unique axis and cell
  choice of monoclinic groups, axis permutation of orthorhombic groups,
  hexagonal or rhombohedral axes of the seven R groups. Table A1.4.2.7 lists
  530 settings; 140 numbers have exactly one, 90 have several. NCrystal
  identifies a setting by the table's choice code appended to the number
  (`227:2`, `14:c1`, `62:cab`, `166:r`), with one deliberate addition: the
  explicit code `abc` for the default setting of the 46 orthorhombic
  numbers with axis permutations, which the table defines in a footnote but
  leaves out of its first column, so that only the 140 single-setting
  numbers have an empty code.
- A symmetry operation $(R, t)$ acts on fractional coordinates as
  $x' = Rx + t$. In the 530 settings $R$ is one of 64 matrices with entries
  in $\{-1, 0, 1\}$ (the 48 signed permutations, i.e. point group $m\bar3m$
  with orthogonal-type axes, or the 24 rotations of $6/mmm$ in hexagonal
  axes), and $t$ is a multiple of $1/24$ (all translation parts are
  multiples of $1/12$, origin shifts between settings multiples of $1/8$),
  reduced modulo 1. Operations are therefore represented exactly.
- The orbit of a site is the set of distinct positions generated by all
  operations; its multiplicity times the site-symmetry order equals the
  group order (the number of operations including centring copies).
- The Laue class (the point group of the rotation parts modulo inversion)
  determines which reflections $hkl$ are symmetry-equivalent and hence
  share $d$ and $|F|^2$.

## Implementation

- **Settings table.** The first three columns of the 530 rows (number with
  choice code, Hermann-Mauguin symbol in the table's computer-entry format,
  Hall symbol), transcribed from the printed 2010 edition and cross-checked
  against the SgInfo web tables, spglib, gemmi and ASE; unit tests repeat
  the comparison against spglib and gemmi so that any change of encoding in
  those libraries is noticed.
- **Settings.** The public `SpaceGroupSettingIdx` holds the 1..530 row
  index; internally a setting exposes its number, choice code, symbols,
  crystal system and setting information (hexagonal-family axes, monoclinic
  unique axis and cell choice, origin choice, orthorhombic axis
  permutation). Setting strings are parsed in a strict mode (NCMAT v8: a
  bare number only for single-setting numbers) and a relaxed mode (a bare
  number selects the default setting); choice codes are matched exactly,
  and a code wrong only in case (spglib-style `166:H`) gets an error naming
  the correct one.
- **Operations.** Generated from the Hall symbol by closure over the
  generators, with the origin shift applied, and cached for the lifetime of
  the program; kept in a canonical order (one representative per distinct
  rotation part, identity first, then the centring copies). Operations
  compose, invert, report their type and order, and convert to and from
  CIF-style strings (`x,-y,z+1/2`).
- **Cell constraints.** The metric tensor must be invariant under every
  rotation part; which relations between cell parameters this implies
  ($b = a$, $\gamma = 120^\circ$, ...) is derived exactly in integer
  arithmetic, and used both to complete cells given with implied parameters
  left out and to check given ones (exact equality required). This replaced
  the per-crystal-system rules with identical verdicts, now derived from
  the setting rather than assumed from the number.
- **Orbits and structure checks.** A site is expanded by applying all
  operations, merging images that coincide within rounding noise (and
  symmetrising the site, so `0.3333` becomes exactly 1/3), and rejecting
  sites that are close to a special position without being on it; the
  tolerances were chosen from the distribution of rounding noise and
  genuine near-coincidences in Crystallography Open Database entries.
  Conversely, positions are grouped into orbits. A structure is checked
  against a setting by mapping its positions with the coset
  representatives and centring translations and measuring the largest
  deviation from the nearest position of the same species; checking all
  settings of a number yields the best-fitting one.
- **Equivalent reflections.** For a setting, the distinct rotation parts
  modulo sign give the list of indices equivalent to a given $hkl$ (half
  of them, the other half being the Friedel mates). This replaced the
  tables per Laue class, which did not distinguish $\bar31m$ from
  $\bar3m1$ (space groups 149, 151, 153, 157, 159, 162, 163 previously got
  wrong structure factors), and makes any declared setting flow through to
  the hkl families.
- **Queries.** `["util","sgsym",SG]` (operations of a setting),
  `["util","eqrefl",SG,"H,K,L"]`, `["util","atomsites",...]`,
  `["util","atompositions",...]`, and the structure and sites queries on
  `Info` objects; `NCMATComposer.verify_crystal_structure` and
  `refine_crystal_structure` (spglib-based, chapter 60) accept any setting
  the library handles and standardise others.

## Validation

- `tests/src/app_sgsym` and `tests/scripts/sgsym.py` (against spglib and
  gemmi): the table, the generated operations of all 530 settings,
  operation arithmetic and parsing, orbits, cell constraints.
- `tests/src/app_eqrefltables` (the new equivalent-reflection code against
  the previous tables for all settings), `app_eqhkl`, `app_symchecks`,
  `app_cellconstraints`.
- `tests/scripts/ncmatsettings.py`, `ncmatsites.py`, `atomsites.py`,
  `latticecells.py`, `cif2ncmatgen.py` (synthetic CIFs in all 230 groups).

## Approximations and limitations

- Only the 530 standard settings; non-standard origins or bases are
  rejected (transform first, e.g. with the composer's spglib refinement).
- Not implemented: point-group classification, Bravais type, chirality,
  transformations between settings (e.g. origin shifts), reflection
  conditions (systematic absences) as a utility, CIF export.
- Hermann-Mauguin symbols are in the table but not yet accepted as input in
  `@SPACEGROUP` nor shown in error messages.
- Data files whose positions do not have the symmetry of their declared
  space group are now rejected.

## New or changed in 5.0.0

Everything in this chapter is new in 5.0.0, replacing the 4.4.6 approach
(default settings assumed, rhombohedral axes recognised from the angles,
Laue-class tables, per-system cell rules), which was correct for the default
settings of all 230 groups except for the $\bar31m$ Laue class. Also new:
`SpaceGroupSettingIdx` in the public API, the NCMAT v8 settings policy and
`@ATOMSITES`, and correct handling of non-default settings such as
monoclinic unique axis c.
